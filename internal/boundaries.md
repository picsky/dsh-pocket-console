# 边界

**一页纸。** 它存在的唯一目的是让下一个改动**更快做决定**：哪些边界是深思熟虑的、哪些只是碰巧没做。仓库里 `docs/decisions/` 记的是"为什么代码长成这样"；**这里记的是"为什么只做这些、以及为什么不做那些"。**

**防变胖约束**：任何一条，如果读的人不需要它就能做决定，它就不该在这张纸上。要展开的理由请去对应的 decision record，不要抄过来。

内部文档，刻意**不**放进 `package.json` 的 `files`，所以不会被发布。

## 0. 证据三级

这条最有用，所以放最前。**同一场讨论里，两个"看起来显然是结论"的判断都被查证推翻了**——它们之所以能一路流动，正是因为假设伪装成了结论。

| 标注 | 含义 |
|---|---|
| **已验证** | 在本仓库或真实环境**实测**过，或读过实现代码/文档原文确认 |
| **推断** | 从代码或文档推出来的，**没有实测** |
| **待验证** | 只有真机能定，且**失败时可能无声** |

## 1. 边界表（每条一句话理由）

### 做

| | 理由 |
|---|---|
| 桌面优先，手机只做**助手**：推进已有工作 | 手机的价值是**便携**，不是屏幕。做成 dsh web 的移植版会同时输给桌面和原生 |
| 审批、提问 → 卡片 | 这两件事会**阻塞** agent，需要人立刻决定 |
| 一轮跑完 → 结果卡 | 会话停下来了，而"该你了"是一个需要人介入的**决定**，不是状态播报 |
| 长任务 → 活动卡（只改不发） | 长任务期间手机收不到任何东西，而"它还在跑吗、跑到哪了"正是此时唯一的问题 |
| 优先侧跟着人走 | 人一旦在手机上处理过，为一张空椅子等专享时间就是在拖延唯一能回答的那个界面 |
| 从手机开下一个任务 | 长任务跑完时人往往不在桌面，而"开下一个 shard"是**只有手机能及时做**的决定。限当前会话的工作区（[0016](../docs/decisions/0016-the-phone-can-start-the-next-task.md)） |
| 出站长连接 | 不需要公网 IP、域名、隧道，也不开端口 |

### 不做

| | 拒绝它的理由 |
|---|---|
| 不开任何入站监听 | 开了就要面对"从任何地方可连"，那是另一个安全模型。代价是手机只能被动收卡 |
| 不搬 GUI / 不做会话管理（列表、搜索、归档） | 搬界面就要搬工作区、会话、设置、凭据。手机不需要它们就能**推进** |
| 不做休眠会话 | 不活跃的会话没人用得上；做了要连带做生命周期、归档、唤醒，全是为一个不存在的场景 |
| 不选工作区 | 卡片是一份决定的凭证。让它能指定路径，等于丢了手机就能在机器上任意目录跑活（[0016](../docs/decisions/0016-the-phone-can-start-the-next-task.md)） |
| 不做 pin | 飞书 pin 是内测能力，且私聊支持情况未文档化 |
| 不用 `open_url` / AppLink / webview | 要我们自己提供一个可访问的网址，等于**开一个端口**，与上一条冲突 |
| 不主动推**状态** | 一个开着的页面或一个忘关的标签页会把"人在手机边"这个真实状态盖掉（[0015](../docs/decisions/0015-desk-presence-is-the-gateways-request-id.md)） |
| 永不自动批准 | **沉默不作数**。插件从不替你决定 |
| 从不改 DSH | 它是 bundle profile 层，只注册在两条已文档化的 waterfall 上。DSH 升级不该弄坏它 |
| 不做迁移/兼容旧版 | 没有维护中的旧分支，版本就是最新发布版 |

## 2. 能力清单（用"人什么时候需要它"刻划）

| 能力 | 人什么时候需要 |
|---|---|
| 审批卡 | 一条命令等着批准，而我不在电脑前 |
| 提问卡（多问题可逐步答） | agent 要我选，而我只有手机 |
| 结果卡 + 回复框 | 一轮跑完了，我要给这个会话下一条指令 |
| 活动卡 | 长任务跑着，我只想知道**它还在不在跑、到哪了** |
| 优先侧切换 | 我在手机上处理过一次，接下来别为一个空椅子等 |
| 手机开新任务 | 一个 shard 跑完了，**下一个 shard 得现在开**，而我不在桌面 |

## 3. 外部能力边界

### 飞书

| 约束 | 证据 |
|---|---|
| 卡片请求体上限 30 KB | **已验证**（文档原文） |
| 回调须 3 秒内应答（长连接也一样） | **已验证**（文档原文） |
| `im.message.patch`：14 天内、单消息 5 QPS、前后都需 `update_multi:true` | **已验证** |
| **编辑一张已发出的卡是静默的**——不响、不产生新消息、列表预览不变 | **已验证**（真实租户实测）。**这是活动卡能成立的全部原因** |
| 平台到底量的是编码前还是编码后的那一层 30 KB | **待验证**。代码按更保守的一层取（文本预算 4.5 KB，见 `budget.js`） |
| 没有"静默消息"这种东西 | **已验证**（文档原文）。注意力只能靠少发，不能靠关掉 |
| 折叠面板不支持内嵌表单 | **已验证**（文档原文） |
| `config.summary` 能否自定义会话列表预览 | **待验证**（文档有，但本地 SDK 类型里没有） |
| pin（`im:message.pins:write_only`）是内测，私聊支持未文档化 | **已验证**（据此拒绝） |

### DSH

| 约束 | 证据 |
|---|---|
| 插件**不能**创建"受限会话"，只能新建或直接给 agent 发消息 | **已验证**（读实现） |
| 新建会话就是 Web 界面走的那条路：`sessionController.create({ cwd, agentPreset? })` | **已验证**（读实现 + 类型） |
| `sessionController.prompt()` 会把调用方 request id 写进消息 source；**其他人类消息路径都不写** | **已验证**（逐个查过。这是桌面判据的基础，见 [0015](../docs/decisions/0015-desk-presence-is-the-gateways-request-id.md)） |
| 该字段**没有任何类型声明**，只存在于运行时的对象上；失效时**静默** | **已验证**（搜遍所有 `.d.ts`）。**这是一处上游依赖风险** |
| 工具结果可达数百 KB，且会话层**没有截断标记** | **已验证**（读实现） |
| 浏览器 composer 的逐题进度够不到（store 是组件私有） | **已验证**（[0012](../docs/decisions/0012-the-desktop-composer-steps-without-the-phone.md)） |

## 4. 渲染政策

**一条判据：这个元素会不会改变你下一句要写什么？**

会 → 留。不会 → 丢。推理与成功过程都不改变你的下一句，所以丢，但**丢了要说明丢过**（否则你无法判断记录是否完整）。

它导出的取舍：

| 元素 | 处置 |
|---|---|
| 人的消息、模型说的话 | **原样保留** |
| 成功的工具调用/结果 | 丢 |
| 失败的工具 | 留一行，**带原因** |
| system 消息、reasoning | 丢 |
| 过程折叠 | **只有冻结的卡**才折 |

## 5. 失败场景表

每加一个功能，**横着问一遍**："在这个场景下它怎么表现？"

| 场景 | 已定行为 |
|---|---|
| 手机没网 / 通道挂了 | 发卡失败进重试（5 秒退避）；桌面分支仍然权威，调用方继续等桌面 |
| `dsh` 中途重启 | 优先侧是持久的（凭据库）；通知是持久的（`notice-store`）；**活动卡的记录不持久**，重启后那张卡停在原地 |
| 两个会话同时跑 | 每个会话一张卡；活动卡上界 64 个会话，通知上界 256 个 |
| 桌面开着但人不在 | **只开着页面不算人在桌面**（[0015](../docs/decisions/0015-desk-presence-is-the-gateways-request-id.md)） |
| 桌面关了人也不在 | 正是本插件存在的场景：等专享时间耗尽后发手机 |
| 审批和结果同时来 | 各自一条新消息，互不覆盖 |
| 连按两下 | 审批：只有settle那次有效，后到的被拒；结果卡：rid 单次使用；新任务卡：用过即收回表单 |
| 一轮里连问两个问题 | 一张卡原地推进（[0011](../docs/decisions/0011-one-question-per-card.md)），**不发新消息**——此时静默正是要的，因为读者正在那张卡上操作 |
| 卡片发出后请求已结束 | 再按会被改写成"该请求已失效"并去掉控件，不再看起来可答 |

## 6. 已知的、不打算修的

这些是**诚实的缺口**，不是选择。写在这里是为了别被当成 bug 反复报。

- **响应丢了 + 通道不认 `uuid` + 平台已接受** —— 客户端无法解决，会变成第二条消息。
- **活动卡不早于手机优先出现**：桌面优先时不发活动卡（桌面看得见），所以桌面期间跑的任务没有记录。
- **冻结卡的记录有上界**，超出时丢的是**最早**的条目。
- **审批卡与结果卡不折过程**，它们只留一句结论。
- **镜像回填需要页面开着**，且窗口只有一分钟。
