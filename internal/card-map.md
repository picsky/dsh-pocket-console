# 卡片地图：每一种卡是什么，什么时候来，按了会怎样

手机这一侧**只有四种面**。这份文档把它们放在一起，因为单独看每个模块都讲不清**数量**——
而"一次运行响几次"恰恰是这个插件的核心承诺，也是唯一会被使用者立刻察觉的东西。

标注：**已验证**＝真机上看过；**代码在**＝实现与测试都在，但这一条我没在真机确认过。

---

## 一张表

| 卡 | 标题 | 什么时候来 | 控件 | 按了之后 | 通知 |
|---|---|---|---|---|---|
| **审批** | `工具审批 · <项目>` | 一条命令等批准，且桌面没在时限内答 | 两个按钮：允许一次 / 拒绝 | **同一张卡被改写成结果**（原地，不新增消息） | 1 次 |
| **提问** | `提问` 或 `提问 · 第 N/M 题` | agent 要我选，且桌面没答 | 单选的每个选项一个按钮 + 自由输入框 + 提交 | **同一张卡原地翻到下一题**；最后一题答完变结果 | 1 次 |
| **执行中** | `执行中 · <项目>` | **手机持有优先侧**时，一轮开始（创建）；**或你在结果卡上回复之后**（接过那张卡，不新发） | **没有控件**（刻意的，见下） | 不可交互 | 创建那一次 1 次；被接过来的不响 |
| **结果** | `结果 · <项目>` | 一轮跑完，且（桌面没优先 或 超时） | 回复输入框 **+** 开新任务输入框 | 回复 → **这张卡自己变成执行中卡**；开新任务 → 收掉控件、留答案与折叠 | 1 次 |

**第一个回合 = 执行中（1 次通知）+ 结果（1 次通知）= 2 条消息；之后每个回合只多 1 条**（新结果卡），
因为回复之后那张结果卡自己就是下一轮的执行中卡（[0021](../docs/decisions/0021-the-card-you-pressed-is-the-one-that-moves.md)）。

---

## 1. 审批卡

- **真源**：内存里的 escalation 记录。**重启即失效**——那之后按卡片只会得到一句"请求已过期"，卡片被改写。
- **控件**：`允许一次` / `拒绝`。**没有其他按钮**：不做"总是允许"，因为这个插件从不替人决定。
- 正文里有一段说明当前是哪一侧：手机持有优先侧时写"**立即**"；桌面优先时写"等了 N 秒对方没答"。
- **答复后**：`record.complete()` 把同一张卡改写成结论文本（`已允许一次` / `已拒绝` / `桌面已答复`），控件消失。**不新增消息。**
- **一条命令只发一次**；桌面那一侧始终是并行的权威分支，谁先答谁算。

## 2. 提问卡

- **一次一题**：`ask_user_question` 有多个问题时，卡片**逐题推进**，标题带 `第 N/M 题`（只有一题时不带序号，避免重复）。
- **控件**：单选 → 每个选项一个按钮 + "其他"输入框 + 提交（`escalation.js:196`）。自由作答 → 一个输入框 + 提交。
- **答复后**：同一张卡原地翻到下一题；全部答完变结论文本。**整个多题问答只占一条消息。**
- 桌面 composer 的逐题进度插件够不到（[0012](../../docs/decisions/0012-the-desktop-composer-steps-without-the-phone.md)），所以手机不等桌面，自己走完。

## 3. 执行中卡（唯一"活的"卡）

**它只在手机持有优先侧时创建**（`activity.js:583`）。桌面优先时**一条都不发**——桌面自己看得见，发一张没人看的卡正是订阅里承诺不做的那种推送。

- **每个会话一条，只创建一次**，此后**永远是原地编辑**。这就是它唯一一次通知的由来（`create` 会响，`patch` 不会）。
- **也可以由回复"接过"一条已有消息**（`adopt`）：你在结果卡上回一句，那张卡从那一刻起**就是**这个会话的执行中卡，不再另发。所以"执行中"和"结果"是两张消息，但**你按的那张永远是会动的那张**。
- **没有控件，这是刻意的**：它每 250 ms 被改写一次，控件在这种卡上等于放在一台正在动的机器上——按下去的时候它可能已经不是你看的那一版。**不是因为"交互过的卡不能改"**：那条早期猜测已被实测推翻（表单提交过的卡继续 `patch` 90 次全部成功，[`boundaries.md`](boundaries.md)）。
- **卡片上有什么**：
  - 状态行：`处理中` / `已结束`，出错时是 `出错`
  - 已用时长（每 5 秒动一次，所以"它还在跑吗"随时可答）
  - 最近 3 段正文片段（只留最新，避免卡片被历史灌满）
  - 工具行：`▸ 读取 ×3`、`▸ 运行命令`——**按动作类型聚合，不显示文件名或命令内容**
  - **冻结后的「本次执行过程」折叠**：只放**你回复的那一轮 + 这一轮**（历史深度 1），人说的那句用 `**你**：` 标出来。**不累计更早的轮次**——那些在它们各自的结果卡里（[0022](../docs/decisions/0022-the-fold-is-one-turn-and-marks-what-you-said.md)）
- **编辑节流**：每 250 ms 最多一次，deltas 累积后重写。所以**回复之后卡片最多 250 ms 才变**。
- **冻结**：一轮结束后它变成"已结束"留档，不再更新（除非最后一次写失败——那会重试到用尽）。
- **真源**：`activity.js` 的内存记录 + `run-record.js` 的过程记录（后者独立于卡片，桌面优先时也在记）。
- **已验证（你实跑过）**：卡片确实出现。

## 4. 结果卡（信息最密的一张）

**它现在承担三件事**，这是[0019](../../docs/decisions/0019-the-next-task-rides-the-result-card.md) 的取舍：

```
<这一轮的答复>                      ← 卡片的主体
**回复这条消息**即可把下一步交给这个会话。   ← 提示，用掉后随控件一起消失
---
或者，在**新会话**里开下一段：
在一个**新会话**里开一轮，工作区沿用这个会话的。
[新会话要做什么？]  ← 第 2 个输入框
[开始新任务]
───
▸ 思考过程                          ← 折叠面板，点标题展开
```

- **两个输入框**：上面的回给**本会话**，下面的在**新会话**里开一段。两个控件的占位文字不同，就是为了不让人分不清（真机观感待验证，清单 G2）。
- **折叠面板里是"这一段做了什么"**（标题 `思考过程`）：从**人说的最后一句**到**它停在哪**，头尾都保留，中间放不下时明说省略了多少字节。**面板只有冻结的卡才有。**人自己说的那句用 `**你**：` 标出来，是面板里唯一被标记的一行（[0022](../docs/decisions/0022-the-fold-is-one-turn-and-marks-what-you-said.md)）。
- **回复之后**：这张卡**变成执行中卡**（[0021](../docs/decisions/0021-the-card-you-pressed-is-the-one-that-moves.md)）——标题换成 `执行中 · <项目>`，正文换成状态行 + 时长 + 最新片段，答复正文与折叠在执行期间**不在卡上**（活着不折叠），这一轮结束后随记录回来。**不新发消息。**
- **回复送进会话的方式看会话在不在跑**（[0023](../docs/decisions/0023-a-reply-into-a-running-session-steers.md)）：**跑着 → `steer` 插进当前这一轮**（和桌面 composer 一样）；**空闲 → 排成下一轮**。真机上发现"跑着时排队的那条指令没兑现"（通知被消费、卡片变了、那一轮没来），所以跑着时改走 steer。
- **开新任务之后**：被用掉的那一段文字**和它的输入框一起**消失，答案和折叠**留着**。
- **过期/被取代时**：同样保留答案与折叠，只把控件换成一个说明。**正在被执行中卡占用的消息不会被这条改写。**
- **每一轮仍然只发一条结果卡**——折叠是搭在这条已经要发的消息上的，不额外发。

## 贯穿四种卡的三条规矩

| 规矩 | 为什么 |
|---|---|
| **能用编辑解决的，绝不新发消息** | 只有 `create` 会通知，`patch` 是静默的（实测）。"少打扰"只能靠少发，不能靠关掉通知——平台没有静默消息这种东西 |
| **会动的那张卡，必须是你按的那张** | 回复之后把结果卡**就地**交给执行中卡（[0021](../docs/decisions/0021-the-card-you-pressed-is-the-one-that-moves.md)）。在另一条消息上显示"它在跑"，等于让读者按一张卡、看另一张卡 |
| **改写必须从"发出时的卡"重建** | 卡片一生会被改写多次（答复、被取代、过期、用掉入口）。用一句话换掉整张脸会把答案和折叠一起吞掉——踩过两次 |
| **改写拿走一个控件时，必须把它那段话一起拿走** | 卡片上留着"或者，在新会话里开下一段"却没有输入框，和丢掉答案是同一类错误，只是更安静 |
| **谁占着这张消息，别人不许改** | 结果卡的"这张卡已失效"分支会改写"按下按钮的那条消息"，而那条消息现在可能正是跑着的那张卡 |

## 一些数字（都是实测或由代码推出）

| 项 | 值 | 来源 |
|---|---|---|
| 第一个回合的消息数 | **2** | 执行中 + 结果 |
| 之后每个回合的消息数 | **1** | 回复接过的结果卡就是下一轮的执行中卡，该轮只新发一条结果卡（[0021](../docs/decisions/0021-the-card-you-pressed-is-the-one-that-moves.md)） |
| 一条多题提问的消息数 | **1** | 逐题原地推进 |
| 一条命令审批的消息数 | **1** | 答复后原地改写 |
| 短信片保留 | 最新 **3** 段 | `RECENT_FRAGMENTS` |
| 折叠里的历史深度 | **1** 轮（+ 本轮） | `TURN_HISTORY`——你回复的那一轮 + 这一轮（[0022](../docs/decisions/0022-the-fold-is-one-turn-and-marks-what-you-said.md)） |
| 活动卡编辑间隔 | **250 ms** | `REFRESH_MS`，也因此同一条消息**最多 4 次/秒**（平台允许 5） |
| 单卡文字预算 | **32 KB**（按转义后的请求体计） | `CARD_TEXT_BUDGET` |
| 整卡请求体预算 | **96 KB** | `CARD_BODY_BUDGET`；实测平台接受 131 KB、拒绝 164 KB |
| 卡片元素上限 | **120** | `CARD_ELEMENT_BUDGET`；实测平台 180 通过、200 被拒 |

## 明确**没有**的东西

- **没有"状态推送"**：插件不主动告诉你"它还在跑"，执行中卡只在**手机持有优先侧**时存在，且创建那一次才响。
- **没有常驻面板**：置顶状态板只有设计（[0018](../../docs/decisions/0018-the-status-board-is-a-pinned-card.md)），**代码未动**。
- **没有"总是允许"**：审批只有一次性的两个按钮。
- **重启后老卡片失效**：审批与提问卡依赖内存记录，重启后按它只会得到"已过期"。
- **读不到历史**：手机上看不到会话列表、历史消息，也**读不回**任何已发的卡片（应用没有读权限）。
