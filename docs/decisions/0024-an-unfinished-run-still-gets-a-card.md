# 0024 — 没跑完的那一轮，也要给手机一张能回复的卡

**Status:** accepted.

## Context

使用者报的：**"报错卡片没有跟回复框，导致报错后无法继续推进。"**

查下来不是"忘了加框"——**回复框长在结果卡上，而报错的那一轮根本不发结果卡**。两道闸门：

1. `results.js` 的 `turn/end`：

   ```js
   if (event.data?.reason?.kind !== 'completed') return
   ```

   只有正常跑完才算数。`error`、`max-tokens`、`aborted`、`blocked` 一律不记 `ended`、不 arm，**没有结果卡**。

2. 就算放开第一道，`fire()` 还有一条：`if (!isAnswer(track.message)) return`，而
   `isAnswer = hasToolCall !== true && text.trim() !== ''`。**报错最常见的结束样子恰恰是最后一条
   assistant 消息带工具调用**（挂掉的那次调用）——`hasToolCall === true`、`text` 为空。

读者手上唯一那张是**执行中卡**，而它**刻意没有控件**（`activity.js` 的 `buildView` 写死
`buttons: []`、`forms: []`——它每 250 ms 被改写一次，控件会被按到过时的那一版）。于是它冻结成一张
只读的卡：标题 `执行中`、状态行 `出错`、失败原因、失败工具，**没有任何入口**。

**报错 = 一张只读的卡 + 没有结果卡 + 只能回桌面继续。**

## Decision

**没跑完的结束也发结果卡——只要"接下来怎么办"是读者的决定。**

- `error` 与 `max-tokens` 进 `UNFINISHED_REASONS`：工作没做完，而拿手机的人正是要决定它要不要继续的人。
- **`aborted` 与 `blocked` 不进**：那是人（或循环）已经做出的停止，按了停止一秒后又来一张"接下来做什么"
  的卡是噪音——而且它会在**桌面**按的停止上响到手机上。
- **"结束在工具调用上"这道闸门只为"跑完"保留**：跑完的一轮如果结束在工具调用，那是过程不是结果，
  一张要读者去回复"没人说过的话"的卡比没有卡更坏（原有行为，专门有用例守着）。没跑完的一轮**不管结束
  在什么上都要发**，因为消息就是"它停了"。
- **正脸说什么**：跑完的一轮有答复，答复就是正脸。没跑完的一轮可能一个字都没有，于是按优先级取——
  **这一轮说过的最新一句**（`track.spoke`，与"是不是答复"分开记，因为一条既说话又调工具的 message
  不是答复，但它的字仍是读者最该看到的）→ 都没有时用一句标题文案（`noticeUnfinished(kind, why)`），
  `error` 带上错误正文，`max-tokens` 说明是输出上限。

卡片仍然是那张结果卡：答复/标题 + **回复框** + 「思考过程」折叠（里面是这一轮做过什么，含失败的工具）。
读者回复之后走的还是 [0021](0021-the-card-you-pressed-is-the-one-that-moves.md) 那条路——**那张卡就地
变成执行中卡**，也就是"继续推进"。

## Consequences

- 一次报错在手机上会看到两张卡：**执行中卡（只读留档，冻结成"出错"）+ 结果卡（带回复框）**。
  和"正常跑完"完全对称——不是为了好看，是因为那是同一件事的两种结局。
- `track` 多两个字段（`spoke`、`reason`），都在 `turn/start` 清掉：一个属于"这一轮说过什么"，
  一个是"这一轮怎么结束的"，两者都是"下一轮不再适用"的东西。
- 尺寸兜底那一层（`clipToBytes`）现在按**正脸文本**算，而不是按 `track.message.text`：正脸不再总是
  那条消息的文本，用错了会让"太长的卡片"重试时把正脸换掉。

## Alternatives

**让执行中卡冻结时带上回复框。** 否决：它正在被高频改写、且完全没有 notice/rid 机制；冻结态与下一轮的
live 态共用同一条消息，控件会被下一轮覆盖。

**出错时不发新卡，而是把那张冻结的执行中卡就地改写成带回复框的结果卡**（0021 的反向：让 notice 去认领
activity 的 handle）。它最贴合"你眼前那张就是入口"，但要再加一条模块间的缝，且与使用者先前定的
"跑完要独立新卡"取向不同。**用户选了发新卡这一条。**

## What would reopen this

- 真机上 `aborted`（例如工具超时导致的中断）也需要"接下来怎么办"——那时它要进 `UNFINISHED_REASONS`。
- 报错卡和跑完的结果卡在手机上难以区分（那时要给报错卡一个不同的 `tone`，现在两种都还是 `info`）。
