# 0019 — 下一段任务搭在结果卡上，而改写不许弄丢答案

**Status:** accepted.

## Context

一个回合跑完，手机上原本会出现**三张卡**：`DSH 执行中`（那一轮的过程）、`DSH 结果`（答复 + 回复框）、
`DSH 新任务`（开下一段的表单）。按通知数算就是**一次运行三次通知**。

而"结果"和"下一段"本来就是同一个问题的两半：结果卡最后一句是"回复这条消息即可把下一步交给这个
会话"，新任务卡问的是"要不要另开一个会话做下一段"。两张卡问同一件事，却各响一次。

## Decision

**下一段任务的入口搭在结果卡上，不再单独成卡。**

具体是：结果卡的视图在**发出之前**由 `work` 模块追加一句引子、一段说明和一个表单；预算是
`view.forms` 追加一项。频道本来就为同一张卡上的两个表单分配命名空间（`form_0_*` / `form_1_*`），
核心也早就在发带两个控件的提问卡，所以两种控件共处一张脸不需要新机制。

于是每次运行的消息数从 3 降到 2：`DSH 执行中`（create，通知 1）→ `DSH 结果`（create，通知 2，
已经带着开新任务的入口）。"执行中"那张卡也不再是一张用完就没用的卡——它是结果卡的前半生。

> 上面这句在 [0021](0021-the-card-you-pressed-is-the-one-that-moves.md) 之后**反过来了**：结果卡是
> **下一段执行中卡**的前半生（回复之后就地接过去）。第一条执行中卡（第一条结果卡之前的那张）仍然
> 是一次 create、一次通知，本条对它不变。

**"执行中"仍单独成卡，这一点是用户选定的（乙：跑完再发一张新卡、响一次）。**

## Consequences

- **一次运行 2 条消息、2 次通知**，比原来的 3 少一条；手机上不再有孤立的「新任务」卡。
- 结果卡承载两个表单，所以**控件名必须从卡上读、不能假设**：回复框和开新任务的框会被频道分别
  命名。测试里用一个 `workField(card)` 从**表单自己报告的名字**里取，而不是取第一个控件——取第一个
  会把新任务打进回复框，而那是另一个问题的另一个控制。
- 结果卡只在**手机持有优先侧**时带这个入口。桌面自己能看见"接下来能做什么"，给坐在桌面前的人
  递一个开新会话的控件，就是答应过不做的那种推送。

### 一个被这次改动暴露出来的既有缺陷

结果卡会被改写两次：读者回复时、有更新的结果取代它时。原实现每次改写都把整张脸**换成一句话**
（"已收到指令"／"已被取代"），于是答案和「思考过程」折叠面板一起消失——读者刚回复完、往回滚，
正在读的东西没了。

改写现在从**发出时的卡**重建：答案在、折叠面板在、只有被用掉的那个控件和指向它的那句话离开。
这条对三个改写点都生效（回复、被取代、过期）。

有一处必须记下来，因为它是**静默出错**的那类：`work.mergeInto` 在"追加"和"收尾"两种用法下都叫
这个名字，公开方法当初只转发了两个参数，于是收尾时走进了"再追加一次"的分支——卡片上出现两份
引子和两个表单，而没有任何报错、测试也只是断言失败。参数名是 `outcome`，第三个位置。

### 第二次踩：改写拿走了控件，却把话说留着

第一版修好之后，回复过的卡片变成：

```
构建已经通过。
---
或者，在**新会话**里开下一段：
在一个**新会话**里开一轮，工作区沿用这个会话的。
**已收到指令**，已排入该会话。
```

**输入框全没了，但那段话还在**，等于告诉读者去用一个不存在的东西。这比丢掉答案轻，但**是同一类
错误**：卡片说了它做不到的事。

根因是边界记错了。结果卡的正文分两层：

| 层 | 内容 | 谁能活过改写 |
|---|---|---|
| 结果 | 答案 + 「思考过程」折叠 | **永远保留** |
| 追加层 | 回复提示、开新任务引子与说明、两个表单 | 用掉之后**整层丢掉** |

`RESULT_ENDS` 一开始记在"回复提示之后"，于是切片时把提示留下了。它现在记在**答案之后**，
一次切片就把追加层连话带控件一起拿掉。规则说一遍：

> **改写拿掉一个控件时，必须把它的话一起拿掉。** 卡片上不许留指向不存在控件的文字。

三个改写点（回复、被取代、过期）现在共用这一条边界，测试里各有一条断言盯着它。

## Alternatives

**保留单独的新任务卡。** 否决：它就是这次要减掉的那条通知，而两张卡问的是同一个问题。

**让结果卡上的按钮先"展开"成表单，再提交。** 否决：更啰嗦，且折叠面板不能嵌套表单；直接把表单
放上去是一次交互就够。

**用一张常驻的置顶卡当"开新任务"的入口。** 否决（见 [0018](0018-the-status-board-is-a-pinned-card.md)）：
常驻状态板必须没有任何控件，否则它一点就被冻住、再也不能更新。入口和常驻面不能是同一张卡。

## What would reopen this

- 真机上发现结果卡带两个表单让人分不清哪个是哪个（那时要把引子写得更明确，或者把表单挪到
  一次按钮点击之后）。
- 平台允许折叠面板内嵌表单，那么"下一段"可以收进折叠里，card face 更干净。
