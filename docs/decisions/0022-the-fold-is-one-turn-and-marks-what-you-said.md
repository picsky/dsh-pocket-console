# 0022 — 折叠只讲这一轮，并且标记你说的那句

**Status:** accepted.

## Context

[0021](0021-the-card-you-pressed-is-the-one-that-moves.md) 之后，读者按的那张结果卡就地变成执行中卡，卡上的折叠开始回答一个**新问题**："我刚发的那句话干了什么？"

但那份折叠不是为这个问题写的。**同一批 `session/event`，两个模块各建了一份"过程"记录**：

| | `activity.js`（执行中卡） | `run-record.js`（结果卡） |
|---|---|---|
| 每条存什么 | **裸字符串**——kind 在记录那一刻就丢了 | `{ text, kind }`，kind ∈ human/model/tool/failure |
| 折叠范围 | `turns`（最近 **5** 轮）+ 本轮 | `readRun` = **本轮**，遇到人说话就重开 |
| 轮边界切在哪 | **`turn/start`** | **人说话时** |
| 首句 | `user/message` 时若还没有记录就丢掉 | 进门就建档 |

一个会话三轮的探针（手机持有优先侧，同一批事件喂给两个模块）把四件事一次暴露出来：

```
执行中卡：第1轮的答复。 / 第2轮：我（人）说的话 / --- / 第2轮的答复。 / 第3轮：我（人）说的话 / --- / 第3轮的答复。
结果卡　：第3轮：我（人）说的话 / 第3轮的答复。
```

- **累计**：执行中卡把三轮都摆出来了（结果卡只有本轮）。每一轮**已经有它自己的结果卡**，这些内容是读者刚读过的。
- **边界错一格**：打开新一轮的那句人话被算进**上一轮**那一组——因为 `turn/start` 开在这一句**之后**。
- **首句丢失**：手机刚接管时会话还没有记录，第一句人话没人接（探针里 `第1轮：我（人）说的话` 整个不在）。
- **没有区分**：人说的和模型说的长得一样。结果卡那边其实**存了 kind**，只是渲染时从来没用；`messages.js` 里也没有"人话"的文案。

## Decision

**折叠只讲这一轮，并且标记人说的那一句。**

- **历史深度 = 1**（`TURN_HISTORY`）：保留**"你回复的那一轮 + 这一轮"**，更早的一律不留。
  保留那一轮不是念旧：卡的正脸已经变成执行中，不保留它，读者按下回复时正在读的那段答复就从手机上消失了。
- **轮边界切在"人说话时"**：他们那句是**新一组的开头**。`turn/start` 退化成兜底——只在"一轮没人说话就开了下一轮"（重试、排队续跑）时把还开着的那组收掉。
- **记录进门就建**：人说的话进来时若还没有记录就建档（**只在手机持有优先侧时**——记录是为卡存在的，给桌面会话建档会把有卡的会话挤出那个有上限的 map）。
- **每条带上 kind**，而折叠**只标记一种**：人自己的话（`**你**：…`）。两张卡的折叠都标记，且都把标记算进各自的字节预算。

## Consequences

- 读到的顺序变成：**你说的那一句 → 它产生的东西 → 一条 `---` → 你说的下一句 → …**。人话是唯一被标记的，所以在模型的一大段话里找自己那句不用重读整段。
- **答复正文仍在手机上**（在上一次回复前的那一组里）；比它更早的轮次不在了——那些内容各自的**结果卡**里都有。
- **一个人在自己那轮还在跑的时候插话**（steering）会把记录切成两组，但**不**清掉正在流的那一步：归档和"卡片正脸重置"是两件事，这里只做前者。否则插话会把还在生成的文本丢掉。
- **仍然有两份记录实现**，口径现在对齐了（本轮 + 标记），但它们是两份代码。`run-record.js` 里那个会话级的读者（`read()`）和 `mergeByKind()` 现在**没有任何调用者**——它们是"两块记录合一"那一步留下的残迹。合并是下一步的事（让 activity 的折叠直接渲染 `readRun`），不是这次的必要条件，记在这里免得下次重新发现。
- 结果卡的折叠在**放不下时**仍是最先丢掉人说的那句（`proseOnly` 那一层）。这次**没改**：它是尺寸兜底，动它要重新量。

## Alternatives

**只放"我回复之后"（严格 run-scoped）。** 用户最初就是这么说的（"只看本次卡片用户回复以及之后的执行过程"），但被他自己改掉了取向：卡的正脸已经变成执行中，那么**他按下回复时正在读的那段答复就彻底离开手机**。保留一轮是这两者之间唯一既不累计、又不吞掉答复的点。

**把两份记录立刻合成一份。** 更彻底，但要先调整 `index.js` 的装配顺序（`activity` 目前在 `runRecord` 之前创建），且这次四件事里三件与合并无关。否决为"现在做"，保留为下一步。

**给每种 kind 都加标记**（模型、工具、失败都标）。否决：全都标等于没标，而读者唯一能在不读全文的情况下认出来的，只有他自己写的那句。

## What would reopen this

- 读者想在手机上翻更早的轮次（那就该有一个真正的"会话历史"入口，而不是把结果卡的折叠当历史用）。
- 真机上出现"一轮结束了但没人说话，下一轮开始时两组被并成一组"——那说明兜底那条路径不够，`turn/start` 的收组条件要重看。
