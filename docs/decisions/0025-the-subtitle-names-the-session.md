# 0025 — 卡片标题下面那行小字，说的是哪个会话

**Status:** accepted.

## Context

卡片标题只带**工作区名**：同一个项目下两个会话在跑，两张卡的标题一模一样，人在手机上分不出哪张是哪张。

```
DSH 结果 · dsh-pocket-console
DSH 结果 · dsh-pocket-console      ← 两张卡，分不出谁是谁
```

会话名本来就是一等属性：harness 会给每个会话一个标题（首条人话兜底、或生成器产出、或人工改名，最新一条赢），
并且保证它**永不进模型输入**。它还是**会话日志里的事件**（`session/title`），而本插件**已经在监听
`session/event`** 这条 firehose——所以拿到它不需要新服务、新权限，也不需要新配置。

难点不在数据，在**观感**：标题一行能放多长？放不下会怎样？

## Decision

**标题不动，会话名放进 header 的 `subtitle`。**

```
DSH 结果 · dsh-pocket-console        ← 标题：这是什么卡 + 哪个项目
会话：新会话任务与手机接管             ← 小字：哪个会话
```

**这是实测选出来的，不是设计出来的。** 探针（真机，`internal/boundaries.md` 有全表）：

| 量到的东西 | 结果 |
|---|---|
| `header.subtitle: { tag, content }` | **接受**（手机上真的多出一行小字） |
| `header.subtitle: "字符串"` | **`230099` 拒绝** |
| 标题长到 **144 显示列**、小字长到 **182 显示列** | 平台都收，**没有硬上限** |
| 标题 87 列 | 手机上**没被截断**；144 列**被截断** |
| 小字过长 | **不跨行，由平台截断** |
| 对着同一个消息 `PATCH` 换小字 | **`code=0`**，手机上跟着变 |

于是：

- **`header.title` 保持今天的样子**（`<前缀> <状态> · <项目>`）——零回归，标题不需要新的分层预算。
- **`header.subtitle` = `<会话：><会话名>`**，**对象形式**（A2 那次拒绝证明它是平台认识的、且严格校验的
  字段，不是 `streaming_mode` 那种"收下但静默无效"）。
- **没有会话名就整行不出现**，不是空行。
- **不裁剪**：小字放不下由**平台**截断——它是唯一知道那行有多宽的地方。这里只做**单行化**
  （各类空白折叠成一个空格）与"空的不算名字"。
- **晚到的名字补得上**：会话名可能由生成器异步产出，而 `PATCH` 能改小字，所以执行中卡下一次改写就带上；
  结果卡则**解析一次、随 notice 携带**（和 workspace 同样的纪律），后续改写（回复、被取代、过期、开新任务）
  都保持同一行。
- **四种卡都带**：审批、提问、执行中、结果——"区分会话"是全局需求，而审批卡恰恰是人盯着某张卡时最可能
  抬头看的那张。

## Consequences

- **新模块 `session-names.js`**：一个有上限的 `会话 → 名字` 缓存，只做一件事——听 `session/title` 事件。
  与插件其余部分同一套纪律（LRU 上限、`observe()` 喂 firehose、`subtitle()` 给卡片）。
- **`identity.js` 多一个纯函数 `sessionName()`**：单行化 + "空的不算名字"。**故意不裁剪**，理由如上；
  这条也写进了单测，免得以后有人"顺手"加个 clip。
- **escalation 的记录多带一个 `session`**：和 workspace 同样的理由——卡片会在请求结算后被改写，而那时
  会话可能已经回收。名字是**渲染时查**而不是拷进记录，因为名字可以晚到。
- **provider 只在有字符串时写 `subtitle`**，而且是 `{ tag, content }`：没有名字的卡，header 与这个字段
  存在之前**逐字节相同**。这条有单测守着。
- 标题会**跟着改名变**（执行中卡每次改写都重查）。这是对的：最新的名字最有信息量。

## Alternatives

**把工作区挪出标题，标题只放会话名。** 用户最初担心的就是标题变长；但会话名与项目名都放不下时必须有取舍，
而"哪个项目"是抬头第一眼要的信息，所以标题留项目、小字放会话名。实测也支持：小字另起一行，不挤标题。

**在标题里塞两个名字（`· 会话名 @ 项目`）。** 探针确认没有平台硬上限，但 87 列已接近手机上能看清的边界，
而会话名上限 80 字节——两个名字加在一起会越过它，且每次都要靠裁剪决定牺牲谁。放弃。

**自己按宽度裁剪小字。** 放弃：小字不跨行、由平台截断，自己裁只会裁得比平台更早、更笨。

**等会话名到了再发卡。** 放弃：一张卡的存在不该等一个生成器。

## What would reopen this

- 真机上小字的截断把名字切得认不出来（那时要自己裁到某个字节数，并把这条改掉）。
- 手机上小字与标题在观感上分不清（那时要给它加个标签样式，或者回到"标题里两个名字"）。
- 会话名开始被用来放别的东西（那它就不再是"哪个会话"的答案）。
